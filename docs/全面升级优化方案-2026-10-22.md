## 1. 建议评审结论

建议把 Easy-Tools 升级成“鼠标旁的办公处理助手”：常用任务一步启动，复杂处理可以预览并保存为流程，用户随时知道正在处理什么、结果去哪、能否停止。

保留 Python + PySide6 + Win32 架构和已有处理器，按“隐私与稳定性底座 → 操作体验 → 工作流 → 办公场景”推进。现阶段不建议整体更换技术栈；当前暴露的问题主要在执行调度、状态管理、表单设计和任务完成路径，换框架不能直接解决这些问题。

四条红线落实为以下产品规则：

| 红线 | 落地约束 | 发布条件 |
| --- | --- | --- |
| 隐私模式是基础能力 | 保持默认开启；覆盖全部新页面、弹窗、预览、错误提示和运行详情；内部截图/OCR 不解除窗口保护 | 隐私专项任何一项失败，阻断发布 |
| 从用户办公问题出发 | 以“整理表格、处理文字、提取截图文字、复用常用内容”等任务组织入口 | 核心场景必须在目标办公软件中完成输入、处理和输出验收 |
| UI/UE 清晰、人性化 | 普通用户不写 JSON、变量表达式和进程名；任务状态、影响范围、失败原因明确 | 首次用户可独立完成常用任务和模板配置 |
| 低配性能与稳定性优先 | 所有任务有上限、取消、超时、资源归属；动效可降级，后台可收敛 | 通过低配压力、长时间运行、异常退出和残留进程验收 |

本文中的新增能力、性能数字、时间安排均为建议或待验收目标，不代表已实现或实测达标。

## 4. 当前问题：按证据与优先级排序

| 优先级 | 观察与源码位置 | 用户影响 | 建议处理 |
| --- | --- | --- | --- |
| P0 | `ui/chain_editor.py::test_run` 在槽函数中同步调用 `runner.run_chain` | 等待、脚本和大量处理会占用 GUI 线程 | 后台运行，显示状态，提供取消 |
| P0 | 同函数仅过滤顶层副作用节点，且使用 `safe or self._steps` | 全部被过滤时会执行原步骤；嵌套分支/循环中的副作用未被过滤 | 执行器统一施加预览策略，递归检查，未知能力默认阻断 |
| P0 | `core/app.py` 的动作、手动链和窗口触发分别新建 daemon Thread | 重复点击/切换可持续创建线程，缺少统一背压与去重 | 统一任务调度和资源限额 |
| P0 | AppService 共用一个 ChainRunner，其取消事件、Python 进程引用为实例状态 | 多条流程并行时存在取消归属和进程管理冲突风险 | 每次执行独立 RunContext；状态按 run_id 管理 |
| P0 | `core/chain.py` 等待使用最长 60 秒的 sleep；循环只有单层次数上限 | 等待期间不能及时响应取消；嵌套循环和流程递归缺少总预算 | 可中断等待、总步数/时长/深度限制、递归调用检测 |
| P0 | `AppService.stop` 未统一取消动作和事件链；模型通过 daemon 回收线程善后 | 退出清理缺乏覆盖全部任务的保证；异常退出存在子进程残留风险 | 关闭状态机、进程树归属和退出专项测试 |
| P0 | `text_input.inject` 焦点恢复失败仍继续注入；`clipboard.copy` 无变化时回退旧文本 | 错窗口输入或把旧剪贴板当新选区处理的风险 | 校验目标身份；失败停止，允许用户显式选择剪贴板来源 |
| P1 | `win32/input.py::paste_text` 延迟后无条件恢复旧剪贴板 | 等待期间用户复制的新内容可能被覆盖 | 用剪贴板序列号/归属判断，仅恢复本次拥有的数据 |
| P1 | StepEditor 使用 JSON args、变量占位符、条件表达式；切类型仅隐藏字段控件 | 普通用户配置成本高，表单标签留空，视觉噪声大 | 参数类型表单、变量选择器、整行显隐、自然语言条件 |
| P1 | 条件/循环通过递归弹窗编辑；流程列表只展示 type | 难看清完整流程，难追踪分支数据从哪来 | 同页缩进步骤树、中文摘要、输入输出连贯预览 |
| P1 | 配置中心“立即运行”按 ID 从已保存 store 查找 | 当前草稿可能与实际运行版本不一致 | 明确“试运行草稿”与“运行已保存版本”，保存状态常显 |
| P1 | schema 接受 hotkey/clipboard_change/timer 等链触发类型；已读调度路径只发现 manual/window_switch，热键回调用于 panel | 配置可接受不等于该链触发已实现 | 建能力清单，仅显示已实现触发方式，未实现项给出明确诊断 |
| P1 | 知识库有缓存，但检索仍逐条评分并收集后排序 | 大知识库耗时与内存峰值随规模增长 | 先基准，后做候选索引、Top-K、有界缓存和文件变化重建 |
| P1 | ConfigStore 读配置使用 JSON 序列化深拷贝；配置页集中构建多个页面 | 大配置的频繁读取和首次打开存在优化空间 | 测量后引入版本化快照、分区通知、页面延迟构建 |
| P1 | 窗口隐私属性设置失败仅记日志，未提供用户可见保护状态 | 用户无法知道某窗口保护未成功 | 分窗口记录实际应用状态，失败阻止敏感内容展示 |

以上“存在风险”的项属于静态审查结论，尚未通过真实低配卡死或异常退出复现；不能把它们直接表述为已定位用户每次卡顿的唯一根因。

## 5. 隐私：固化为界面和执行层契约

### 5.1 窗口保护规则

- 保留当前默认开启和用户选择；任何升级、配置迁移、导入、换主题、精简模式均不得静默关闭保护。
- 统一 PrivacyWindowManager，复用现有全局过滤器；管理窗口创建、句柄重建、保护应用、失败重试和状态查询。
- 新增页面、对话框、工作流预览、运行详情、Toast、菜单和错误界面全部纳入窗口清单与保护测试。
- 高敏感窗口先显示无敏感内容的壳，确认句柄保护应用成功后再填充内容；失败维持遮罩，在受控界面提供重试。
- Qt 应用内提示替代不能继承保护的系统通知；文件选择器、原生菜单、系统对话框和安装器单独审查。无法保证保护的敏感交互优先使用应用内实现，并测性能与可访问性。
- 页面内长期显示“隐私模式已开启”，保护失败显示“当前窗口保护未成功”；只表示本应用可确认的状态，不宣称对所有采集工具绝对不可见。
- 内部截图/OCR 继续处理目标应用，不允许临时设置 WDA_NONE 来获取 Easy-Tools 自身内容。

### 5.2 数据保护规则

- OCR、剪贴板、样本文本和运行预览默认仅在内存使用；运行记录默认只保留时间、状态、耗时和错误码，不保存原文。
- 提供“一键清除临时内容”；关闭结果窗口、任务结束、超时和退出均释放对应大对象。清除按应用管理范围定义，不承诺清除第三方服务或操作系统历史。
- 本地处理与联网调用分别标示。云端调用展示目的地址、发送字段和内容预览；首次或目的地/数据范围变化时再次确认。
- 隐私模式下的发送预览和授权弹窗同样受窗口保护；本地模式不静默回退云端。
- 外部模型导入不复制明文凭据到普通配置；新增连接使用 Windows 凭据安全存储方案，导出配置和模板去除密钥。
- Python 继续默认未信任；修改脚本或导入模板后重新授权。用代码摘要绑定授权，并递归覆盖子流程。预览模式默认禁用任意脚本；用户主动进入真实脚本测试时清楚标注权限和副作用。
- 日志集中脱敏，异常消息也需过滤；模型原生日志单独检查轮转和原文泄漏，不直接打包进诊断报告。

## 6. UI/UE：围绕任务完成重组

### 6.1 两个使用层级

**鼠标旁面板：负责快。** 搜索、固定常用、当前软件适用、最近使用和正在执行状态；保留现有触发习惯和键盘操作。最近使用只记动作标识，不记处理原文。不在弹出路径初始化 OCR/模型或扫描文件。

**主工作台：负责清楚。** 建议一级导航：常用工具、工作流、文本片段、知识库、运行任务、设置。隐私状态常驻，软件更新和数据导入导出归入设置；保留托盘直达入口。

“常用工具”按用户目的分组：文字整理、表格处理、截图提取、常用内容、快捷打开。将“动作库、特定操作区规则”等术语留在管理层，用“在哪些软件显示”替代 zone/processes 等字段。

### 6.2 统一任务交互

```text
选择内容来源 → 设置少量选项 → 看处理前后 → 复制 / 回填 / 另存
                    ↓
              保存成我的工具或工作流
```

- 简单、已固定参数的常用动作保持一键执行，不强迫每次进入完整向导。
- 有破坏性或有歧义的操作先预览；保留任务输入快照，失败不覆盖原内容。
- 回填前核验启动时目标 HWND、进程和当前前台；不匹配时停止回填，并保留“复制结果”出口。
- 不宣称对任意软件通用撤销；明确“恢复本次剪贴板”与“撤销目标文档修改”的区别，只在能可靠实现时提供后者。
- 重复点击显示当前任务，不重复创建；长任务显示处理阶段、已耗时和取消，失败提供重试或复制结果。
- 表单有默认值、即时校验和示例；高级参数折叠。ID 自动生成，软件从当前窗口/运行程序中选取，图标可视选择。

### 6.3 全系统设计规范

- 统一字体、间距、边框、焦点、图标和按钮主次；统一中文“保存、取消、试运行、停止”。
- 每页一个主要动作，工具栏与详情区稳定布局；表单隐藏时标签一起隐藏。
- 完整覆盖空白、加载、处理中、成功、失败、取消和未保存状态；错误写清“发生什么、数据是否改变、下一步怎么做”。
- 支持 Tab、方向键、Enter、Esc、Ctrl+S，清晰焦点及可访问名称；数字快捷键避免与文本编辑冲突。
- 在 1366×768、100%/125%/150%/200% DPI、混合缩放双屏、屏幕断开时验证可见性，避免按钮被挤出窗口。
- 动效只用于反馈和状态切换，建议 100–160ms；低配/减少动态效果时关闭动画和高成本阴影，不影响任何功能与隐私。
- 首期完成高可读性的统一浅色主题；深色主题在对比度和性能验收后扩展，避免首期同时扩张验收面。

## 7. 事件链升级为“工作流”

### 7.1 从模板开始，按步骤理解

首页提供“从模板创建”“从空白创建”“导入”；模板先给用途、输入和输出示例，再展示步骤。旧事件链名称和内容可继续查找。

建议界面结构：

```text
整理客户名单                       未保存    隐私已开启
从选中文本读取 → 清理空行 → 按指定列去重 → 预览后回填
────────────────────────────────────────────────────────
步骤                           当前步骤设置
① 获取选中内容                 按哪一列去重？ [客户名称 ▾]
② 清理空行                     重复时保留     [第一条   ▾]
③ 按列去重  ←                  输入 [第②步结果 ▾]
④ 预览并回填                   输出：清理后的表格
  ＋ 添加步骤                  高级选项 ▸
────────────────────────────────────────────────────────
试运行：使用粘贴的样本，不改变目标文档
输入预览 | 输出预览 | 每步状态与耗时        [试运行] [停止]
                                          [保存] [取消]
```

- 采用可拖动、可键盘重排的步骤卡片；条件与循环同页缩进展开，不靠多层模态窗口理解流程。
- 普通模式用“上一步结果、指定步骤结果、剪贴板、输入样本、变量”选择器，点击插入变量标签。
- 有表头时用列名；无表头显示“第 1 列”，执行层再转换成内部 0 起始索引。
- 条件用“文本 / 包含 / 关键词”“行数 / 大于 / 数量”等表单组合，显示自然语言摘要；正则放高级设置。
- 步骤参数按统一节点定义自动渲染。节点元数据包含字段类型、默认值、输入输出类型、所需权限、副作用、超时和可预览能力。
- 保存前检查未填写字段、缺失动作、无效变量、前向/失效引用、类型不匹配、嵌套与递归预算；定位到具体步骤。
- 步骤使用稳定 ID，排序不改变引用语义；复制、删除、撤销与重做保持数据一致。旧 stepN 引用迁移时需显式转换或提示修复。

### 7.2 安全预览与真实执行分开

**预览**：使用用户粘贴的样本，或经过用户主动采集的输入快照；替换真实剪贴板写入、键盘输入、文件写入、打开程序和联网调用，展示“将执行什么”。策略由执行器下沉执行，递归覆盖分支、循环和链调用，不靠 UI 删除若干节点实现。

**真实执行**：执行用户保存的明确版本；展示实际目标、外发与文件写入范围，可取消。已经完成的外部副作用不能因取消被当作自动回滚。

- 默认预览不运行 Python、外部命令和未知扩展；允许在显式授权的真实测试中运行，并以不同按钮和状态区分。
- 每步提供状态、耗时、输入/输出摘要；完整内容只在受保护详情中按需查看，大结果截断显示并允许导出。
- 取消为每次运行独立令牌；等待可中断；可终止的子进程设硬超时，普通线程采用协作取消，不把 Future 超时当作线程已结束。
- 首期开放手动与已验证触发方式。窗口自动触发默认关闭，配冷却、同链互斥、目标过滤和失败熔断；剪贴板/定时触发待专项验收后再开放。

## 8. 办公提效场景与范围

## 9. 性能和稳定性底座

### 9.1 统一执行生命周期

新增 TaskManager，逐步接管动作、工作流、OCR、知识库导入、问答和更新任务；UI 只提交请求并接收 GUI 线程信号。

- 每次运行具备 run_id、不可变配置版本、目标窗口快照、取消令牌、deadline、状态和资源清单。
- 建议初始预算：交互轻任务与磁盘/网络任务分队列；低配重任务并发 1，标准并发最多 2；键盘/剪贴板提交通道并发 1；手动待执行队列最多 8，重复自动触发合并或丢弃并给出状态。
- 工作流不要在占满的线程池中同步提交子任务并等待同一线程池，避免调度死锁。由编排层调度，或将每条流程作为完整 worker 执行。
- 全局取消、单任务取消、窗口关闭和程序退出均到达实际 worker。网络取消关闭连接或等待有界超时，不能只隐藏进度条。
- 工作流设总步数、嵌套深度、总耗时和输出大小上限；超限明确停止并保留已完成情况，参数在基准后确定。

### 9.2 进程与卡死隔离

- 模型、脚本及需要硬超时的计算使用可管理子进程；结合 Windows Job Object 或等效受控进程树机制确保父进程退出时清理应用拥有的子进程。
- 明确哪些打开程序属于用户任务结果，不将其误判为应终止的 worker；不能按进程名结束用户的其他模型或 Python 程序。
- 对脚本派生进程、进程启动中取消、启动失败、父进程崩溃和更新交接做专项验证；进程隔离保证可管理性，不是账户权限沙箱。
- OCR 的线程限制保留；如果底层原生推理无法可靠取消，将其迁移到受控 worker，超时后回收并重建。基于实测决定持久 worker 的空闲释放时间，避免每次 OCR 都冷启动。
- 退出顺序：拒绝新任务→停触发与钩子→取消排队/运行任务→限时回收 worker→关闭日志/托盘→释放单实例标记。保留总退出期限，不能在 GUI 无限 join。
- 更新助手需要在主进程退出后继续的场景单独移交归属，防止进程清理机制误杀更新程序。

### 9.3 低配专项

- 轻量模式不加载 OCR/模型直到需要；本地模型空闲一段时间后释放（初始建议 3–5 分钟），再次调用显示加载状态。按需补齐模型可重启状态机。
- 缓存按字节数和条数双限制；禁止把无限历史、全部 OCR 图片或所有步骤完整输出常驻内存。
- 知识库先记录 1 万/5 万/10 万条的加载、检索和内存，再选择倒排候选索引及 Top-K；重建后台完成，用新索引原子替换。
- 不在 GUI 读取大文件/网络盘；大文件检查体积、行数和解析预算，超限给出拆分或分批建议，避免资源耗尽。
- 保留面板现有分页和渲染键缓存；配置变化只失效相关分组，搜索按数据筛选而不是逐键重建大量控件。
- 配置采用版本化、只读快照与分区变更通知，避免高频 JSON 深拷贝；先保持 API 兼容，禁止共享可变字典污染配置。
- 主工作台按页延迟构建；列表优先模型/视图和按需加载，大表格预览限制可见行并后台分页。
- 降低阴影与重绘成本；前台状态监听按需启停、合并变化，优化前后记录 CPU 与触发延迟，不盲目提高轮询频率。
- 主进程和 llama 日志均设大小/轮转限额；诊断只采耗时、队列、线程、内存、句柄等元信息，不默认上传。

## 10. 量化验收目标（待评审、待实测）

基准环境建议：Windows 10 22H2 / Windows 11，2 核 4 线程、4GB 内存、集显、SATA SSD；另测普通办公电脑和 8GB HDD 设备。固定输入数据和系统负载，分别记录冷/热启动。

| 项目 | 建议目标与测量口径 |
| --- | --- |
| 冷启动到托盘可用 | 低配机器 p95 ≤ 3 秒，不含用户主动启动 OCR/模型；至少 30 次 |
| 热面板呼出 | 物理触发到首帧可操作 p95 ≤ 150ms；1000 次开关，无持续恶化 |
| 搜索/切分类 | 1000 个动作下 p95 ≤ 100ms；记录配置规模与输入方式 |
| UI 响应 | 长任务时 GUI 心跳延迟 p95 ≤ 100ms；不得出现持续超过 1 秒的主线程阻塞 |
| 轻量空闲资源 | OCR/模型均未加载，预热后 10 分钟平均 CPU ≤ 1%（整机口径）；主进程 Private Bytes 初始预算 ≤ 180MB |
| OCR/模型资源 | 分别记录 worker 内存和 CPU；OCR+模型合计的初始内存预算 ≤ 900MB，预算不足时串行/释放，不影响面板；以实测决定最终上线阈值 |
| 文字与表格 | 固定 1MB 文本、1 万行×10 列 TSV：处理 p95 ≤ 2 秒；先定义正确性样例，超过阈值仍可取消 |
| 知识库检索 | 固定 5 万条题目，热检索 p95 ≤ 500ms；冷加载单独统计，期间界面可操作 |
| 取消 | 协作任务 p95 ≤ 300ms 响应；受控子进程任务停止/回收 ≤ 2 秒；报告不能立即回滚的副作用 |
| 退出 | 正常退出及有任务时退出 ≤ 3 秒；应用拥有的模型/脚本进程树 ≤ 5 秒清理，无继续触发输入 |
| 长期稳定 | 24 小时混合负载；固定静止检查点的 Private Bytes 净增长 ≤ 30MB，线程数/句柄数无单调增长；异常均有明确状态 |
| 隐私 | 页面/弹窗清单全部覆盖；支持的系统捕获路径与实际使用的录屏工具专项验收；切句柄/换屏/切模式无敏感首帧泄漏 |

若 PySide6 运行时或目标设备使初始资源预算无法达到，应先提交测量拆分和优化收益，再评审阈值调整；不能静默降低隐私、正确性和稳定性标准来换数据好看。

## 12. 兼容迁移、回退与验证

- 配置引入明确版本，迁移前备份原配置；旧版 actions、snippets、rules、chains 保留稳定标识和内容，避免默认配置覆盖用户列表。
- 迁移只对副本执行：校验→迁移→比对数量/引用→原子写入。任何一步失败保留原文件，允许导出诊断及人工修复。
- 未知节点/未实现触发器保留但禁用运行，并展示原因；不静默删除。新模板与用户动作合并需要去重和可见确认。
- UI 草稿与运行配置隔离；保存成功后切换版本，运行任务继续使用启动时快照；配置并发写入加版本冲突检测。
- 提供受控新旧编辑器切换用于过渡，新流程不能被旧编辑器静默降级。预览安全策略和隐私约束不能随旧界面回退。
- 程序回退必须同步恢复可兼容配置备份；旧版不认识的新配置不能直接覆盖。发布走现有渠道和灰度机制，方案阶段不直接发布。

验证分层：

1. 单元测试：权限/副作用递归检查、取消归属、队列饱和、引用迁移、预算、剪贴板归属和目标窗口变化。
2. UI 自动检查：新窗口保护接入、整行显隐、草稿保存、错误定位、键盘路径和 DPI 布局。
3. 真实桌面：Excel/WPS/Word/浏览器/远程桌面、中文输入法、混合 DPI；确认原窗口、结果和剪贴板行为。
4. 故障注入：脚本死循环/派生进程、OCR 失响应、模型启动中退出、网络断开、文件占用、磁盘写失败、后台队列满、重复点击、父进程被结束。
5. 隐私专项：应用每类窗口、菜单、原生对话框、错误提示、试运行详情、切模式和句柄重建；实际截图/录屏路径检验。测试本身也要避免暴露用户真实办公内容。
6. 候选包：干净账户安装、覆盖升级、数据保留、取消更新、回退和卸载。不可在有真实配置的环境执行现有会删除 APPDATA 的 smoke_exe.py。
