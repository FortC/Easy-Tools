## 修复内容

- 文件在目标目录同卷暂存，再通过 `os.replace` 原子替换，避免直接覆盖时截断目标 DLL。
- 对 Windows `PermissionError` 有界重试。多文件升级记录同目录旧文件备份；单个文件持续拒绝访问时回滚此前替换的程序文件。失败提示说明退出 Easy-Tools、检查目录权限或安全软件，并指出旧文件仍被保留。
- 桌面和开始菜单快捷方式通过 Windows Shell COM 创建，不再启动 PowerShell 子进程。

## 当前账户临时目录实装

仅使用合成 EXE、DLL 和文本文件，安装目标位于 `%TEMP%` 的独立目录；测试短暂写入并在结束时恢复了当前用户卸载注册项和现有快捷方式。

- 当前用户注册表中的 `InstallLocation` 与版本值正确，卸载删除了归属该临时安装的注册记录。
- 桌面和开始菜单快捷方式均创建成功；卸载只删除指向临时安装的快捷方式，并保留原有快捷方式内容。
- 覆盖升级保留了清单外用户文件并删除了旧版内部 DLL。
- 无控制台卸载器删除了清单内程序文件，保留清单外用户文件。
- 安装目录位于临时目录而注册表同时可能指向临时路径时，旧版本检测仍优先常规安装目录。

上述验证已用最终生成的 `0.4.1` 安装器再次执行，使用其内置载荷覆盖同一个临时目录后卸载；安装器及卸载器均为实际构建产物。

## 尚存清理项

- 卸载器为避免删除正在运行的自身，会把一次性 worker 复制到 `%TEMP%\Easy-Tools-Uninstall-<id>` 后再清理安装目录。Windows 测试确认安装目录与注册项清理正常，但这个很小的临时 worker 文件夹会在 worker 退出后留在 `%TEMP%`。本次验证创建的临时目录已手动清理；自动清除 worker 副本还需单独设计和验证，因此本记录不把卸载描述为删除所有临时痕迹。
