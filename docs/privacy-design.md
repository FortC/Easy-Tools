# Easy-Tools 隐私设计约束

本文件适用于后续新增的界面、动作、事件链、AI、截图和 OCR 功能。隐私保护属于产品的持续约束，新增功能不得绕过以下要求。

## 窗口捕获

- 所有 Easy-Tools 顶层窗口（包括面板、配置中心、对话框、截图与答案窗口）都必须继承 `CapturePrivacyFilter` 的捕获排除状态。
- Easy-Tools 发起截图、OCR、Canvas 等内部流程时，不得临时移除自身窗口的捕获排除属性。
- 新建对话框必须由 Qt 应用持有，并让全局过滤器能观察到显示事件；不可创建绕过过滤器的独立原生窗口。
- 该机制只覆盖受支持 Windows/DWM 捕获 API；不得承诺阻止直接读取进程内存、窗口控件数据、辅助功能接口或物理拍摄。

## OCR、AI 与外部工具

- OCR 文本、选区、剪贴板文本及知识库内容默认只在本机处理。
- 云端模型或外部工具只有在用户主动选择并了解发送内容后才能收到数据；明确展示服务类型、数据范围和目的地址。
- CC Switch 配置凭据仅在调用时只读使用，不写入 Easy-Tools 配置、普通日志或错误弹窗。
- 新增 MCP、邮件、HTTP 工具时必须为连接凭据提供安全存储方案、超时/取消及发送前授权流程；不能仅凭配置 JSON 中的 URL 或密钥就静默外发。
- Python 脚本节点必须默认未信任、显示其拥有当前账户权限并由用户明确授权后才运行；用独立进程和超时隔离卡死/崩溃，不得把它描述成能阻止脚本读文件、联网或截屏的安全沙箱。明确提示自定义脚本可能自行采集屏幕并绕过 Easy-Tools 窗口捕获排除。
- 调试日志不得记录完整问题、OCR 内容、剪贴板内容、文件内容或令牌。

## 变更检查

每个触及上述数据或窗口的功能都应补充隐私回归验收，并检查已有截图、OCR、答案展示及窗口捕获排除行为未被改变。详见 `_doc/prd/ET-PRIV-001-window-capture-privacy.md`。
